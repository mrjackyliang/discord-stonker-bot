Check what you need before you install, from a Docker host and local storage to a <Terminology title="Your bot's entry in the Discord Developer Portal" to="/docs/reference/terminology#discord-basics">Discord application</Terminology> and optional API keys.

## Requirements

- **Docker** — Run the published `mrjackyliang/discord-stonker-bot` image with `docker run`, or build it from the repository with Docker Compose.
- **An amd64 or arm64 machine** — The image builds only for these two processor architectures.
- **Local storage for the <Terminology title="The Docker volume where all your data lives" to="/docs/reference/terminology#appliance-and-services">data volume</Terminology>** — PostgreSQL keeps its files in a Docker volume, and it is recommended to keep that volume on a local disk rather than NFS or SMB.
- **The source code (Compose only)** — Building with Compose needs a copy of the repository.
- **A <Terminology title="Your bot's entry in the Discord Developer Portal" to="/docs/reference/terminology#discord-basics">Discord application</Terminology>** — You create it in the Discord Developer Portal and copy its <Terminology title="The bot's password for Discord, from the Developer Portal" to="/docs/reference/terminology#discord-basics">Bot Token</Terminology>, as described in [Discord Application](/docs/getting-started/discord-application/).
- **<Terminology title="An intent you must switch on in the Developer Portal first" to="/docs/reference/terminology#discord-basics">Privileged intents</Terminology> for your features** — Features that read message text or member events need intents you switch on in the Developer Portal.
- **Optional reCAPTCHA keys** — The <Terminology title="A public page that hands out short-lived Discord invites" to="/docs/reference/terminology#invite-page-and-webhooks">invite page</Terminology> needs a <Terminology title="Google's checkbox that keeps bots off the invite page" to="/docs/reference/terminology#invite-page-and-webhooks">reCAPTCHA</Terminology> v2 site key and secret key.
- **Optional alert accounts** — [Notifications](/docs/control-panel/notifications/) need an account or address on the service they post to, such as an ntfy topic, a Telegram bot, or an SMTP server.
- **An HTTPS address for remote use** — Secure session cookies and <Terminology title="Sign in with Face ID, Touch ID, or a security key" to="/docs/reference/terminology#sign-in-security">passkeys</Terminology> need HTTPS and a domain name, or `localhost`, as described in [Remote Access](/docs/operations/remote-access/).

## Network and Ports

- **Control panel** — The web service always listens on every address on port 22604. The supplied `docker run` command and Compose file use host networking, so it is the container's only open port and is available on every host address. To use another host port, switch to bridge networking and publish the fixed container port, such as `"8080:22604"`.
- **Database** — PostgreSQL listens only on a Unix socket inside the container and opens no TCP port, so nothing outside the container can reach it, even with `--net=host`.
- **IPv6** — Host networking exposes the control panel on the host's IPv6 addresses when IPv6 is enabled. Those addresses are often reachable from the internet, so it is recommended to check that your router or host firewall blocks inbound connections to port 22604.
- **Connections to Discord** — The bot, the <Terminology title="Background service that runs schedules and deliveries" to="/docs/reference/terminology#appliance-and-services">worker</Terminology>, and the <Terminology title="A public page that hands out short-lived Discord invites" to="/docs/reference/terminology#invite-page-and-webhooks">invite page</Terminology> connect to Discord over the internet.
- **Optional connections** — The <Terminology title="A public page that hands out short-lived Discord invites" to="/docs/reference/terminology#invite-page-and-webhooks">invite page</Terminology> connects to Google's <Terminology title="Google's checkbox that keeps bots off the invite page" to="/docs/reference/terminology#invite-page-and-webhooks">reCAPTCHA</Terminology> service, and RSS feeds connect to each feed's host over HTTPS.
- **Notifications** — The <Terminology title="Background service that runs schedules and deliveries" to="/docs/reference/terminology#appliance-and-services">worker</Terminology> connects to each notification <Terminology title="One place alerts go, such as a chat, topic, or inbox" to="/docs/reference/terminology#notifications">destination</Terminology>'s service, and the web service does too when you select **Send test**.

## Container Runtime

- **Identity** — The container starts as root so Nova can prepare ownership and the time zone. s6 then runs PostgreSQL, the bot, the control panel, and the worker as `PUID:PGID`, each from 1 through 60000.
- **Writable state** — Persistent app state belongs under `/config/keys/` and `/config/database/`. `/data` is retained only for compatibility with an old state mount and is not new app storage.
- **Shutdown time** — The image's s6 timing values keep the full shutdown inside Docker's default 10-second stop window.
- **Restart policy** — Docker restarts the container after a stop or failure because the supplied run line and Compose file use `always`.

The `docker run` command uses `--restart always`.
