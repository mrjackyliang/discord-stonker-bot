Look up what happened to each section of the <Terminology title="The old v3.4.3 bot that ran from a config.json file" to="/docs/reference/terminology#legacy-migration">legacy bot</Terminology>'s `config.json` in the rewrite, from changed features to removed integrations.

## How to Read the Matrix

- **Feature sections** — Each of the 19 feature sections maps to one feature with the same settings key.
- **Settings** — The `settings` section maps to the <Terminology title="The bot's password for Discord, from the Developer Portal" to="/docs/reference/terminology#discord-basics">Bot Token</Terminology> and the server's profile.
- **Market data and Twitter** — The `api-fetch` and `twitter-feeds` sections have no counterpart in the rewrite.

The <Terminology title="Where each old setting landed in the rewrite" to="/docs/reference/terminology#legacy-migration">feature matrix</Terminology> summarizes what the rewrite does today for each <Terminology title="One top-level key in the old config.json" to="/docs/reference/terminology#legacy-migration">legacy section</Terminology>, and the feature pages give the details.

Choose **An older config.json** in the [Backup wizard](/docs/control-panel/export-and-import/#import-an-older-configjson) to bring the supported sections across.

## Removed Capabilities

- **Twitter and X** — Feeds, tweet publishing, and copier destinations are gone.
- **Market data** — The `api-fetch` lookups and their commands are gone.
- **<Terminology title="An old !command; slash commands replace it" to="/docs/reference/terminology#legacy-migration">Prefix commands</Terminology>** — Text commands such as `!ban` are replaced by <Terminology title="A /command members type in Discord's message box" to="/docs/reference/terminology#discord-basics">slash commands</Terminology>.
- **Separate web servers** — The web helpers no longer run their own HTTP and HTTPS servers.
- **Invite page templates** — The `invites.ejs` file isn't imported, and the **Invite page** designer builds the page instead.
- **Command-driven permission toggles** — Permission toggles run only on their schedule.

## Intent Changes

The <Terminology title="The old v3.4.3 bot that ran from a config.json file" to="/docs/reference/terminology#legacy-migration">legacy bot</Terminology> always requested 12 <Terminology title="A kind of Discord event the bot asks to hear about" to="/docs/reference/terminology#discord-basics">Gateway intents</Terminology>, including all three <Terminology title="An intent you must switch on in the Developer Portal first" to="/docs/reference/terminology#discord-basics">privileged intents</Terminology>. The rewrite always requests the Guilds intent and adds others only for enabled, valid features, and it never requests the Presence intent.

| Intent          | <Terminology title="The old v3.4.3 bot that ran from a config.json file" to="/docs/reference/terminology#legacy-migration">Legacy bot</Terminology> | Rewrite                                                                                                                                                                                                                                    |
|-----------------|-----------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Presence        | Always                                                                                                                                              | Never                                                                                                                                                                                                                                      |
| Server Members  | Always                                                                                                                                              | Only for anti-raid, impersonator alerts, role features, member <Terminology title="One kind of audited event, sent to its own channel" to="/docs/reference/terminology#feature-settings">audit routes</Terminology>, and most server tools |
| Message Content | Always                                                                                                                                              | Only for message-reading features and the audit link and edit routes                                                                                                                                                                       |

[Permissions and Intents](/docs/reference/permissions-and-intents/) lists each feature's intents.
