Look up the <Terminology title="A %PLACEHOLDER% the bot fills in when it sends" to="/docs/reference/terminology#feature-settings">message variables</Terminology> each feature fills in, and the variables used by <Terminology title="A URL that turns signed JSON into a Discord message" to="/docs/reference/terminology#invite-page-and-webhooks">mapped webhooks</Terminology>.

## How Variables Work

- **Writing one** — Type the variable exactly as shown, with its percent signs, in a message field.
- **Feature support** — Each feature fills in only the variables listed for it, and any other variable stays in the message as written.
- **Variable buttons** — Message fields in the feature editor show a button for each variable that feature supports, and selecting one inserts it at the cursor.
- **Mentions** — A variable that becomes a mention shows the member or channel, but never notifies them.

`%YEAR%` uses UTC everywhere except scheduled posts, which use the rule's <Terminology title="The zone a schedule's times are read in; UTC by default" to="/docs/reference/terminology#schedules-and-jobs">time zone</Terminology> at the scheduled time. `%CHANNEL_TAG%` is a clickable channel mention.

Message proxies have no message field, so they fill in `%YEAR%` in the text they relay, including text that <Terminology title="A find-and-replace applied before a message is relayed" to="/docs/reference/terminology#feature-settings">replacements</Terminology> add.

Regex rule and affiliate cleanup direct messages, auto replies, and suspicious-word alerts don't fill in any variables, even where their message fields show the variable buttons.

## The Invite Page

The <Terminology title="A public page that hands out short-lived Discord invites" to="/docs/reference/terminology#invite-page-and-webhooks">invite page</Terminology> has no placeholders. The designer fills in the server's name, icon, member count, and boost level for you, as described in [Web Applications](/docs/features/web/web-applications/#invite-page-designer).

## Webhook Variables

A <Terminology title="A URL that turns signed JSON into a Discord message" to="/docs/reference/terminology#invite-page-and-webhooks">mapped webhook</Terminology>'s message uses <Terminology title="An @PLACEHOLDER@ filled from the webhook's JSON" to="/docs/reference/terminology#invite-page-and-webhooks">webhook variables</Terminology> written as `@ID@`, filled from fields in each request's JSON. [Signed Webhooks](/docs/reference/signed-webhooks/#map-json-fields-to-variables) explains each variable type.
