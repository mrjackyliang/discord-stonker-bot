Look up the <Terminology title="Placeholder the bot fills in when a message sends" to="/docs/reference/terminology#message-variable">message variables</Terminology> each feature fills in, and the variables used by <Terminology title="Endpoint that turns signed JSON into a channel message" to="/docs/reference/terminology#mapped-webhook">mapped webhooks</Terminology>.

## How Variables Work

- **Writing one** — Type the variable exactly as shown, with its percent signs, in a message field.
- **Feature support** — Each feature fills in only the variables listed for it, and any other variable stays in the message as written.
- **Variable buttons** — Message fields in the feature editor show a button for each variable that feature supports, and selecting one inserts it at the cursor.
- **Mentions** — A variable that becomes a mention shows the member or channel, but never notifies them.

| `%YEAR%`                | The current year                                                                                                                                                                                     | Anti-raid <Terminology title="Roles and welcome text given after rules screening" to="/docs/reference/terminology#membership-gate">membership gate</Terminology>, role messages, scheduled posts, message proxies, <Terminology title="Endpoint that turns signed JSON into a channel message" to="/docs/reference/terminology#mapped-webhook">mapped webhooks</Terminology> |

`%YEAR%` uses UTC everywhere except scheduled posts, which use the rule's <Terminology title="IANA zone name such as America/New_York" to="/docs/reference/terminology#time-zone">time zone</Terminology> at the scheduled time. `%CHANNEL_TAG%` is a clickable channel mention.

Message proxies have no message field, so they fill in `%YEAR%` in the text they relay, including text that <Terminology title="Find-and-replace rule applied before text is relayed" to="/docs/reference/terminology#replacement">replacements</Terminology> add.

Regex rule and affiliate cleanup direct messages, auto replies, and suspicious-word alerts don't fill in any variables, even where their message fields show the variable buttons.

## The Invite Page

The <Terminology title="Public page that gives an invite after reCAPTCHA" to="/docs/reference/terminology#invite-page">invite page</Terminology> has no placeholders. The designer fills in the server's name, icon, member count, and boost level for you, as described in [Web Applications](/docs/features/web/web-applications/#invite-page-designer).

## Webhook Variables

A <Terminology title="Endpoint that turns signed JSON into a channel message" to="/docs/reference/terminology#mapped-webhook">mapped webhook</Terminology>'s message uses <Terminology title="Placeholder filled from a field in the request's JSON" to="/docs/reference/terminology#webhook-variable">webhook variables</Terminology> written as `@ID@`, filled from fields in each request's JSON. [Signed Webhooks](/docs/reference/signed-webhooks/#map-json-fields-to-variables) explains each variable type.
