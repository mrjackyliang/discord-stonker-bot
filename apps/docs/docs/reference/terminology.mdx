Short, practical definitions for the appliance, Discord, control panel, and feature terms used throughout the Stonker Bot for Discord documentation. Tables list the term first, also known as, then the definition.

## Appliance and Services

| Term                 | Also known as                      | Definition                                                                                                                                                                                                                                                                                                                                                                                                  |
|----------------------|------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **appliance**        | —                                  | The single Docker container that runs the whole bot. Inside it, s6-overlay supervises PostgreSQL 17, the web service and control panel, the worker, the Discord bot, and the state and database setup jobs.                                                                                                                                                                                                 |
| **worker**           | —                                  | The background service that checks schedules about once a second and delivers queued posts, RSS items, permission changes, webhook messages, and notifications. It talks to Discord through the REST API, not the Gateway.                                                                                                                                                                                  |
| **data volume**      | `stonker-data`                     | The folder or Docker volume mounted at `/config`, with PostgreSQL under `database/` and private key material under `keys/`. `docker compose down` keeps it, and `docker compose down --volumes` deletes it.                                                                                                                                                                                                 |
| **installation key** | `installation.key`, credential key | The 32-byte encryption key stored at `/config/keys/installation.key` as 64 lowercase hexadecimal characters plus a newline. It encrypts the Bot Token and every other saved secret with AES-256-GCM. Version 4.0 kept the raw bytes at `/config/secrets/credential.key`, and a newer start moves and converts it. A `pg_dump` backup does not include it, and losing it means entering those secrets again. |
| **readiness check**  | `GET /ready`                       | The endpoint that returns HTTP 200 when PostgreSQL answers and HTTP 503 when it does not. Docker's separate health check requires every long-running service and `GET /health` to pass.                                                                                                                                                                                                                     |
| **heartbeat**        | —                                  | The latest status a service recorded in the database, listed on the Overview page under **Services**. The web service writes one every 15 seconds, and the worker and bot at least every 30 seconds.                                                                                                                                                                                                        |
| **event kernel**     | `connectGateway`                   | The code that compiles each server's features, combines their intents, registers their event handlers, and signs the bot in to Discord. It lives in `apps/bot/src/index.ts`.                                                                                                                                                                                                                                |

## Discord Basics

| Term                       | Also known as       | Definition                                                                                                                                                                                                                           |
|----------------------------|---------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Discord application**    | —                   | Your bot's registration in the Discord Developer Portal, which owns the Bot Token, the privileged intent switches, and the install link. The control panel learns its ID the first time the bot connects.                            |
| **Bot Token**              | —                   | The secret the bot uses to sign in to Discord, copied from the Bot page of your Discord application and entered on the **Connection** page. It is not the Application ID, Public Key, or Client Secret, and it is never shown again. |
| **server ID**              | guild ID            | The number Discord uses to identify a server. The control panel discovers servers on its own, and the Overview page shows the selected server's ID with a copy button.                                                               |
| **Discord ID**             | snowflake           | A 17- to 20-digit number that identifies a Discord user, channel, role, or thread. Settings without a picker take a typed ID, which Developer Mode in Discord lets you copy.                                                         |
| **Gateway**                | —                   | Discord's live connection that delivers server events to the bot. **Start** opens it and **Stop** closes it, while the control panel, worker, and database keep running.                                                             |
| **Gateway intent**         | intent              | A category of Discord events the bot subscribes to when it connects. It always requests the Guilds intent and adds others only for enabled, valid features across every server.                                                      |
| **privileged intent**      | —                   | An intent you switch on for your application in the Discord Developer Portal before the bot can request it. This bot uses Message Content and Server Members, never Presence.                                                        |
| **Message Content intent** | —                   | The privileged intent that lets the bot read the text of messages. Message-reading features such as auto replies, suspicious words, regex rules, copiers, and proxies need it.                                                       |
| **Server Members intent**  | —                   | The privileged intent that delivers member join, leave, and update events. Anti-raid, impersonator alerts, role messages, role synchronization, and every server tool except the emoji summary need it.                              |
| **role hierarchy**         | —                   | Discord's rule that a member or bot can manage only roles below its own highest role. Role synchronization, the membership gate, `/stonker-role`, and `/stonker-bulk-ban` check it first.                                            |
| **slash command**          | application command | A command such as `/stonker-members` that members run from Discord's message box. The Server Tools feature registers up to six per server, and each reply is visible only to the person who ran it.                                  |
| **Discord webhook**        | webhook URL         | A channel URL that posts messages without using the bot's own account. Message copiers and proxies can post through one, and the control panel stores it as an encrypted secret.                                                     |
| **rules channel**          | guidelines channel  | The channel a server sets as its rules or guidelines channel in Discord's server settings. The invite page creates invites for it and pauses invites when the server has none.                                                       |

## Accounts and Access

| Term                | Also known as | Definition                                                                                                                                                                                              |
|---------------------|---------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **setup code**      | —             | The one-time code, such as `K7Q2M-XR9TD-P4W8N`, that the web service prints to the container log while no account exists. It creates the Owner account, lasts 30 minutes, and changes on every restart. |
| **panel role**      | role          | The access level of a control panel account: Owner, Administrator, Operator, or Viewer. Each account has one, and its access tokens can never do more than it allows.                                   |
| **Owner**           | —             | The one account created at setup with the setup code. It can do everything on every server, and nobody can change, suspend, or delete it on the **Users** page.                                         |
| **Administrator**   | —             | A role that can do everything, including adding, changing, and removing users. One limited to chosen servers can only manage users whose servers are all inside its own.                                |
| **Operator**        | —             | A role that changes features, the Bot Token, the invite page, and notifications, and starts, stops, and restarts the bot. It can't manage users or open **Backup**.                                     |
| **Viewer**          | —             | A role that can see the bot's status, features, invite page, and logs but can't change them or open **Notifications**. Its access tokens can only read features and logs.                               |
| **server access**   | —             | The Discord servers a control panel account may open: every server or a chosen list. Other servers are refused, and every-server accounts also get servers the bot joins later.                         |
| **browser session** | session       | The sign-in a browser keeps after you sign in, stored in the database and a cookie. It lasts 24 hours and survives container restarts.                                                                  |
| **access token**    | `dsb_` token  | A personal token starting with `dsb_` that a script sends in the `Authorization` header to call the control panel's API. It acts as its creator, limited to its scopes, and is shown only once.         |
| **scope**           | —             | One kind of API request an access token may make: `bot:control`, `features:read`, `features:write`, or `logs:read`. A role can only give a token scopes it could use itself.                            |
| **trusted proxy**   | —             | A loopback or private address, such as a reverse proxy on the same host, whose `X-Forwarded-*` headers the web service believes. Headers from any other address are ignored.                            |

## Running the Bot

| Term                     | Also known as          | Definition                                                                                                                                                                                                                     |
|--------------------------|------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **server discovery**     | —                      | The automatic listing of every server the bot can see, with its text channels and roles. It runs on connect, on joining or leaving a server, and on channel or role changes; servers it no longer sees are marked unavailable. |
| **desired state**        | —                      | Whether you last asked the bot to run or stop, which decides whether the panel shows **Start** or **Stop**. It starts as stopped and also decides whether the worker and public routes do any work.                            |
| **bot status**           | —                      | The bot's last reported connection state: Online, Starting, Stopped, Stopped by an error, Not connected, or Not responding. The sidebar status card and the phone header pill show it on every page.                           |
| **revision**             | `generation`           | A counter that tells a running bot to reconnect and load the latest settings. Start, Stop, Restart, Bot Token saves, feature saves and switches, and Backup imports all increase it.                                           |
| **example settings**     | Start from the example | The example values **Start from the example** loads into a feature that isn't set up yet. They come from a test setup, so their channels and roles show as unknown and their secret fields start empty.                        |
| **configuration issues** | —                      | The errors that kept the bot's own features off the last time it connected, listed on the Overview page under **Bot**. The rest of the bot still connects, and worker and web feature errors show in their own logs instead.   |
| **encrypted secret**     | —                      | A credential, such as an API key, a webhook URL, or a signing secret, that the control panel encrypts and never shows again. The form shows **Saved** with a **Replace** button.                                               |

## Sign-In Security

| Term                  | Also known as | Definition                                                                                                                                                                                                                              |
|-----------------------|---------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **authenticator app** | —             | An app, such as Google Authenticator, that generates six-digit codes for two-factor sign-in. Turning it on in **Sign-in and security** also gives you 10 recovery codes.                                                                |
| **recovery code**     | —             | A one-time code, such as `K7Q2M-XR9TD`, that you can type instead of an authenticator code when you sign in. You get 10 when you turn on the authenticator app, shown only once.                                                        |
| **passkey**           | —             | A sign-in method that uses your device, such as Face ID, Touch ID, Windows Hello, or a security key, instead of a password and code. It works only at the address it was added on, which needs HTTPS and a domain name, or `localhost`. |

## Backup and Import

| Term                 | Also known as        | Definition                                                                                                                                                                                                                      |
|----------------------|----------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Confirm it's you** | —                    | The fresh account check before an export or import, using your password and authenticator code or a passkey. It gives the browser session a five-minute, one-use confirmation for that operation.                               |
| **export file**      | —                    | A portable JSON backup of the sections chosen under **Settings** → **Backup** → **Export…**. It holds that configuration and its secrets in plain text, but never users, passwords, sessions, logs, or raw access-token values. |
| **legacy import**    | An older config.json | The **Backup** import source that converts the legacy bot's file for the selected server. It checks every recognized section, keeps invalid features off, and replaces the server's features and secrets in one step.           |

## Feature Settings

| Term                     | Also known as                                   | Definition                                                                                                                                                                                                   |
|--------------------------|-------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **trusted role**         | Who can use it                                  | A Discord role you allow to run a bot command, set in a server tool's "Who can use it" field. The member also needs the command's Discord permission.                                                        |
| **alert channel**        | —                                               | The channel where a feature posts alerts or ban reports for moderators. Anti-raid, impersonator alerts, scammer alerts, suspicious words, and affiliate cleanup each have one, and so does each audit route. |
| **observation-only**     | —                                               | A feature that alerts moderators but never bans, kicks, times out, or deletes anything. Impersonator alerts, scammer alerts, and suspicious words work this way.                                             |
| **membership gate**      | New member access                               | The anti-raid setting that gives members roles and posts a welcome message after they complete Discord's membership screening.                                                                               |
| **regular expression**   | regex                                           | A JavaScript text pattern, up to 512 characters with up to 16 flag characters, used to match names or messages. Matching is case-sensitive unless you add the `i` flag.                                      |
| **excluded roles**       | `excluded-roles`, Roles to ignore, Exempt roles | The roles whose members a regex rule or affiliate cleanup skips. Server administrators and owners are not skipped unless they hold one of these roles.                                                       |
| **normalization**        | —                                               | The text cleanup a feature applies before it compares names or phrases, such as stripping accents, lowercasing, and turning styled letters like `Ｍｏｄ` into plain ones. Each feature applies its own mix.     |
| **audit route**          | —                                               | One type of audited event, such as member joins or message edits, sent to its own channel. Audit notifications has nine, and the ones you set up decide which intents the bot requests.                      |
| **message variable**     | placeholder                                     | A placeholder such as `%MEMBER_MENTION%` or `%YEAR%` that the bot fills in when it sends a message. Each feature supports its own set, and unsupported ones stay as written.                                 |
| **replacement**          | —                                               | A find-and-replace rule, written as a regular expression, that message copiers and proxies apply before relaying text. A rule can have up to 50, and without the `g` flag only the first match changes.      |
| **permission overwrite** | —                                               | A channel-level setting that allows or denies permissions for one role or member. Permission toggles replace the whole overwrite for each target they list.                                                  |

## Schedules and Jobs

| Term                  | Also known as | Definition                                                                                                                                                                                                          |
|-----------------------|---------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **calendar selector** | —             | The months, dates, weekdays, hours, minutes, and seconds that decide when a schedule runs, plus its time zone. An omitted list matches every value except seconds, which defaults to 0.                             |
| **time zone**         | `time-zone`   | An IANA name, such as `America/New_York`, that a schedule uses to read its calendar selector. Each schedule defaults to UTC, whatever the container's `TZ` says.                                                    |
| **skip dates**        | `skip-dates`  | Up to 366 `YYYY-MM-DD` dates, in the schedule's time zone, when a scheduled post or permission toggle does not run. RSS feeds do not support them.                                                                  |
| **durable job**       | job           | A queued task, such as a post, a permission change, or a notification, that the worker keeps in the database until it finishes. A failed job retries after 30 seconds and stops after `JOB_ATTEMPT_LIMIT` attempts. |
| **replay window**     | —             | The 24 hours of missed schedule times the worker catches up on after it has been down. Times that pass while the bot is stopped are skipped, not replayed.                                                          |
| **deduplication key** | —             | A unique name for each job, built from the server, the rule, and the scheduled time, that stops the same job from being queued twice. Signed webhook requests and RSS items use one too.                            |

## Notifications

| Term                         | Also known as | Definition                                                                                                                                                                              |
|------------------------------|---------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **notification destination** | destination   | One place the bot sends alerts about itself, such as an ntfy topic, a Telegram chat, or an email inbox. Each uses one of 11 services and chooses its own notification events.           |
| **notification event**       | event         | Something the bot can send an alert about, such as **Bot disconnected** or **Job gave up**. There are six, and a new destination starts with every one checked.                         |
| **secret field**             | —             | A destination setting, such as a bot token, a password, or a webhook URL, sealed with the installation key and never shown again. Leaving it blank when you edit keeps the saved value. |
| **notification payload**     | payload       | The JSON body that webhook and Reverse Proxy for ntfy destinations receive, with `event`, `title`, `message`, `details`, and more. Its `app` is always `discord-stonker-bot`.           |

## Invite Page and Webhooks

| Term                 | Also known as         | Definition                                                                                                                                                                                |
|----------------------|-----------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **invite page**      | —                     | A public page at your `/invite` or `/join` path that creates a short-lived Discord invite after a visitor passes reCAPTCHA. Each invite lasts 60 to 3,600 seconds and allows 1 to 5 uses. |
| **reCAPTCHA**        | reCAPTCHA v2          | Google's check that blocks automated requests on the invite page. The page uses the v2 checkbox and needs a site key and a secret key from Google.                                        |
| **mapped webhook**   | signed webhook        | An endpoint under `/webhooks/` that turns a signed JSON request into a Discord channel message. Each server can have up to 25.                                                            |
| **signing secret**   | —                     | The shared secret, at least 32 characters, that signs requests to a mapped webhook. The control panel stores it as an encrypted secret.                                                   |
| **HMAC signature**   | `X-Stonker-Signature` | The hex HMAC-SHA-256 of `<timestamp>.<raw body>`, made with the signing secret and sent in `X-Stonker-Signature`. The Unix timestamp goes in `X-Stonker-Timestamp`.                       |
| **freshness window** | —                     | The five-minute limit on how far a signed request's timestamp may differ from the server's clock. Requests outside it get HTTP 401.                                                       |
| **webhook variable** | —                     | A placeholder such as `@SYMBOL@` that a mapped webhook fills from a dot path in the request's JSON. A missing value shows as "Unavailable".                                               |

## Legacy Migration

| Term               | Also known as | Definition                                                                                                                                           |
|--------------------|---------------|------------------------------------------------------------------------------------------------------------------------------------------------------|
| **legacy bot**     | v3.4.3        | The original Stonker Bot for Discord, release v3.4.3, which ran as one process configured by a `config.json` file. This rewrite replaces it.         |
| **feature matrix** | —             | The inventory of what happened to each legacy capability in the rewrite, listing every legacy section with its new feature and the main changes.     |
| **legacy section** | —             | One top-level key of the legacy `config.json`. There are 22: `settings`, 20 that match features, and `twitter-feeds`, which the Backup wizard drops. |
| **prefix command** | —             | A text command, such as `!ban` or `!members`, that the legacy bot read from chat messages. The rewrite uses slash commands instead.                  |
